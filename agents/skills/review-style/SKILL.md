# Stylistic code review for a branch

## Process

1. Review all changes in the given branch, or in the current branch if none is given, from the stylistic perspective.
   - The branch might be given as a branch name, pull request number, pull request URL, etc.
   - Review code duplication, too large modules and functions, styles of comments and documentation, and any other potential refactoring.
   - Review code styles and naming conventions that are inconsistent within the changes or with the existing code base if that seems to be unintentional.
2. Show a full review report.
